# 0.1.0 验证记录

日期：2026-09-09。环境：Windows 10 x64（19045）、.NET SDK 10.0.401。测试资料均为程序合成，不使用客户资料。本报告区分真实输出验证、应用视觉检查和仍待其他设备覆盖的部分。

## 已执行的核心测试

| 模块 | 实测与断言 |
| --- | --- |
| 图片 ZIP | 116.29 MB 合成 JPEG 包 → 18.41 MB，20 MB 上限内；12 张图片均保持 2048×1536，说明文件与目录完整，原 ZIP SHA256 未变；约 65.7 秒 |
| 无损与图片转换 | 透明 PNG 逐像素 RGBA 一致；JPG/PNG/WebP 真实解码、比例尺寸、多帧 GIF 每帧导出；取消与原件哈希保护 |
| ZIP 错误边界 | 路径穿越、链接、重复目标、5 GiB 展开上限、20,000 条目限制、无法达到目标、提前取消；19.6 MB 小于 20 MB 上限视为达标但提示余量少，恰好 20 MB 不达标 |
| PDF 图像 | 3 页 A4 / 300 DPI；100 页 A4 / 150 DPI 逐页与 1240×175500 PNG 长图，PNG CRC、完整解压和像素尺寸校验；100 页组合测试约 47.6 秒 |
| 可编辑文档 | DOCX 与 PPTX 包内确实有中英文可编辑文字，OpenXmlValidator 零结构错误；合并拆分、取消、损坏/加密文件拒绝 |
| OCR | 随包 PP-OCRv6 Small 识别中英文、大小写与数字，长截图顶部/底部文字均保留；默认模型路径测试避免只在开发目录可用 |
| 音频 | 24 秒双声道 WAV 4608.1 KB → MP3 168.4 KB，目标 200 KB；M4A 目标；16/24-bit WAV/FLAC 解码样本精确往返；拒绝浮点转 FLAC 和无法保持 32-bit 精度的输出 |
| 视频 | 12 秒、640×360 MP4 3788.8 KB → 835.4 KB，目标 900 KB；H264/AAC、原时长/尺寸/音轨保留；输出全量解码 |
| 媒体错误边界 | 损坏输入、过小目标、取消终止进程、无部分结果发布、含特殊字符的路径安全传参 |
| 文件整理 | 文件和目录按名查找、图片过滤、空查询/失效路径/取消；改名预览、交换文件名、撤销、重名保护、改名后文件被编辑则拒绝撤销 |

图片 ZIP 测试为了达到目标，使用了有损质量 30。这仅证明该样本可达标、无缩尺寸及内容结构完整，**不代表任意 100 MB 包都能压到 20 MB，也不代表压缩前后视觉质量相同**。

测试命令、固定样本与断言保存在 `tests/Shunshou.SmokeTests`；本机详细产物位于忽略入库的 `artifacts/smoke`。

## UI 和便携包

应用使用自己的 WinUI RenderTargetBitmap 输出五分类与 OCR 页面的浅色/深色界面图片。已实际查看主压缩、PDF、图片、文件和 OCR 页面，并压紧布局，使上传上限、质量选项、保存目录和开始按钮在默认窗口完整显示。

已修复首次启动导航图标、发布漏带 XBF/PRI、中文 EXE 需要同名 PRI 三个实际启动问题。独立发布目录的中文入口能输出六个页面的截图；便携目录中的内置模型中英文 OCR、PNG→WebP、PDF 栅格与可编辑 DOCX、ZIP、随包 FFmpeg WAV→MP3 和完整解码检查均通过。检查使用实际便携 EXE 和其自身目录中的运行时，不借用开发目录 FFmpeg。

构建脚本检查必需的界面资源；静态审计 322 个 PE 候选，缺失必需本地依赖为 0。详细包级结果在本机 `artifacts/package-final`，界面图在 `artifacts/ui/package-final`。GitHub Actions 已配置，云端结果应以实际运行状态为准。

## 验证边界

- 通过了生成文件的结构和内容检查，不等于逐一人工比较任意复杂排版文档，也没有声称 OCR 100% 正确。
- 没有在干净 Windows 10/11 虚拟机或 ARM 机器验证；此包仅面向 x64 预览体验。
- 没有用户真实 100 MB 压缩包，因此无法对那一包给出确定的可达体积或画质评价。
- Word/PPT 重建以文字为主。复杂图表/公式/表格版式恢复、7z/RAR、全盘索引与卸载管理不在本次初版验收范围。
- 自动化检查涵盖核心处理和界面渲染，尚未通过外部 UI 自动化逐一操作原生文件选择器、拖放与系统打开行为。
