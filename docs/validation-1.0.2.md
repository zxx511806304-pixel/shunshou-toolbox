# 1.0.2 录屏与搜索定向验证

## 通过的检查

- 实际录制由程序生成的动画窗口，以及生产路径的显示器内局部区域。输出 H.264 MP4：960×800 / 30 FPS、864×720 / 15 FPS、640×360 / 30 和 60 FPS；解码帧内容变化，静音模式无音轨，不覆盖上次文件。暂停 2.1 秒未计入导出时长。
- 录屏启动取消不留下候选文件，随后能再次开始；模拟音频采集中断后，仅发布正常收尾且可解码的有效 MP4，保持错误状态并明确给出保存文件；后续正常录制仍成功。
- 实际 WinUI 录制页面验证预设、自定义分辨率 / 视频码率 / FPS、非法帧率、倒计时取消、暂停继续和停止保存。生成视频中不含浮动控制条；实际查看了解码画面及浅色、深色、切回浅色和展开高级设置的界面截图。
- 区域选择验证正反方向拖动、负坐标、边界、最小尺寸、Esc / 右键 / 失焦取消；快捷键冲突、撤销注册、重复使用和资源回收通过。十次选择后 GDI 对象数 10→10。
- 搜索实际点击同一个按钮完成首次准备 / 等待 / 查询；模拟未启用、取消、授权拒绝和组件缺失，不退回慢扫描。已有 Everything 的生成中文文件查询实测 411 ms。首次提示和浅深色界面已实际查看。
- 最终分发包录屏界面再次实录成功；最终 EXE 通过隔离目录的真实解压流程及模拟桌面快捷方式检查，没有更改用户现有安装、桌面或注册表。ZIP 的 1,234 个清单文件哈希核对通过，包含新增录屏依赖和原链接 / MIT 许可，不含测试偏好或私钥原文件。
- 原生依赖扫描覆盖 573 个候选文件。微软 SDK 官方 win-x64 载荷中的 `Microsoft.Windows.Workloads.Resources_ec.dll` 是有代码的架构伴随组件，只有精确路径与已核验 SHA256 匹配才允许该例外，仍检查导入依赖；没有按文件名通配放行。

## 实际限制

- 只测新增录屏、搜索和打包，不重跑全部工具。
- 本机默认声音输出处于静音、音量 0；系统声录制创建 AAC 音轨，但未验证实际声音信号。保留原始测试失败及环境证据，不算作音频内容通过。没有改变用户音量、默认设备，也没有采集真实麦克风。
- 混合 DPI 多屏视觉、不同显卡、长时间录制、真实麦克风、首次索引 UAC 及干净电脑建库未实测。帧率与分辨率选项仍受实际硬件、驱动及 Windows 编码能力限制。

- [最终包界面](validation/1.0.2/packaged-recording-ui-results.json)、[安装验证](validation/1.0.2/setup-ui-verification.json)、[交付文件校验值](validation/1.0.2/release-artifacts.json)在封装后保存到源码仓库；包内应用文件没有再次修改。
