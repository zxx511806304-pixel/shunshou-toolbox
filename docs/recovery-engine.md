# 0.3.0 误删恢复

恢复入口位于“文件搜索整理 → 误删恢复”。本版把不同来源的候选放进同一个列表，支持按文件名、原路径文字和扩展名筛选，再预览和复制选中的文件。它不修复磁盘、分区表或文件系统，也不把“能找到记录”当作“原文件完整”。

## 查找方式

| 方式 | 实际读取内容 | 名称与范围 |
| --- | --- | --- |
| 综合查找 | 实际磁盘依次查回收站、NTFS 记录、文件内容；镜像依次查记录与内容 | 部分方式不适用或失败时保留其他结果并说明 |
| 回收站 | 所选磁盘当前用户的 `$Recycle.Bin` 元数据与对应文件，包含已删文件夹中的文件 | 元数据有效时显示原名、原路径和删除时间；选中恢复只复制，保留回收站内容 |
| 删除记录 | DiscUtils.Ntfs 0.16.13 的公开读取 API，解析 NTFS 主文件表和默认数据流 | 元数据还在时可能取得原名；原路径仅供显示，不参与写出 |
| 深度扫描 | PhotoRec 7.2 按文件签名和内容查找 | 通常失去原名和目录，可能包含当前仍存在的文件及不完整候选 |
| 已有备份 | 手动选择的现有文件夹 | 列出可读取的备份文件；不自动查找 Windows 历史版本或云端备份 |

“文件名”和“格式”过滤已找到的候选，不代表按旧文件名直接定位被覆盖的磁盘数据。格式可用 `jpg, png, pdf, docx` 等多个扩展名。深度扫描不能承诺找回原名；只有匿名候选时，仍可按格式和预览筛选。

## 输入与 NTFS 边界

可选择可读的本机磁盘或原始镜像文件。实际磁盘的删除记录和深度扫描需要管理员权限；没有权限时可通过界面的明确操作重新打开管理员窗口。镜像使用普通只读文件句柄，不需要为读取一个可访问文件额外提升权限。

删除记录路线要求输入起始处就是 NTFS 卷引导记录；不会自动从带分区表的整盘镜像中定位 NTFS 分区。此类镜像可尝试深度扫描。当前 NTFS 读取器支持主文件表单个属性内的多个数据区段，以及普通删除文件的多个数据区段；磁盘地址读取带扇区对齐和卷长度边界。

本版只处理默认数据流，跳过跨记录属性列表、压缩、加密、稀疏、重解析或损坏记录，不恢复额外数据流。如果主文件表自身需要跨记录属性列表，整个删除记录路线会拒绝读取。单次最多检查前 2,000,000 条主文件表记录、保存 100,000 个候选，并为目标卷保留至少 256 MiB 空闲空间。遇到限制会停止或跳过并在结果中说明。

这些边界不等于损坏磁盘支持承诺。删除后的数据块可能已被其他文件占用，运行中的系统和其他程序也可能继续改变源盘。SSD TRIM、覆盖写入、损坏介质或丢失元数据都可能使恢复失败。不要为了尝试恢复而在源盘上安装、解压软件或保存结果；优先从另一个磁盘运行工具箱，并使用其他卷存放副本。

## 输出、预览与停止

实际磁盘的保存位置必须在另一个本机卷。检查比较 Windows 卷身份而不只比较盘符，也检查已有父目录，避免 `SUBST` 等别名绕过。无法确认卷身份时拒绝继续；目标不能经过符号链接或目录联接，不能位于源备份文件夹内部，也不接受网络共享作为恢复目标。普通镜像是只读文件，允许将结果存于同卷的另一个目录。

记录恢复和深度扫描在所选目标下建立独立的 `Recovery_<时间>_<标识>` 会话目录，保存 `candidates`、`session.json` 及适用的引擎诊断文件。恢复列表中的文件是候选副本或现有回收站 / 备份中的文件。“恢复选中”另复制到用户指定目录，使用安全文件名和平铺布局；不会按 `OriginalPath` 创建旧目录，也不会覆盖同名文件。遇到重名会增加后缀，写文件使用 `CreateNew`，失败时只清理本次创建的不完整副本。

综合查找根据大小和 SHA256 对照，隐藏与有名结果相同的匿名深扫候选。不同名称或版本的有名结果保留；读取失败时保留两边。合并只影响列表，已有候选文件不删除。哈希比较用于识别当前候选间的相同内容，不能证明它与删除前的原件一致。

图片和短文本可在界面预览；支持对当前 PNG、JPG、BMP、GIF 图片进行离线文字识别。TIFF 可预览，但恢复页面不提供 TIFF OCR。预览能解码、长度核对成功或 OCR 有文字，都不能作为文件完整性的证明。大型文件或不支持的类型需在保存副本后用相应软件检查。

停止会取消托管读取，或终止并等待独立 PhotoRec 进程退出；已取得的候选及会话资料保留。扫描中止、空间不足或引擎未完成时会明确提示。候选仍可能不完整，不提供虚构的恢复成功率。

## 实现约束

- NTFS 来源只用只读句柄与不支持写入的有界流。磁盘元数据中的路径分隔符、ADS 冒号、设备名和超长名称不直接决定输出路径；内部候选名带记录编号，使用新建文件语义防碰撞。
- 唯一外部恢复程序是未经修改的 PhotoRec 7.2；不分发或调用 TestDisk 的恢复写出、磁盘修复和分区编辑功能。
- PhotoRec 通过 `ArgumentList` 接收固定只读扫描命令；不执行 shell、不接受用户自定义引擎命令。配置明确禁用自定义签名，防止用户配置改变文件扩展名规则。
- PhotoRec 工作目录设为全新候选目录，`/d files`、日志和用户目录 / 临时目录环境均使用短相对路径指向当前安全会话，避免原生固定长度路径缓冲区截断绝对目标。匹配的 `63/cygwin` 终端定义随引擎携带。
- PhotoRec 7.2 内部使用普通文件创建和重命名，不具备本项目 `CreateNew` 的全部语义。独立会话隔离已有用户文件，但不承诺原生引擎同次扫描中每一个重复候选都单独保留；最终选中复制由 C# 安全写出完成。
- 开始恢复或恢复 OCR 后，应用日志关闭直到进程退出。`--recovery` 启动从入口即禁用日志，跳过自动桌面初始化，只使用已存在的只读运行租约；不存在时要求先正常打开软件。正常首次启动在选择源盘之前可能已经写过运行记录，这些写入不能撤回。该约束也不控制 Windows 或其他程序的磁盘活动。

代码入口为 [RecoveryService.cs](../src/Shunshou.Core/RecoveryService.cs)、[NtfsDeletedFileReader.cs](../src/Shunshou.Core/NtfsDeletedFileReader.cs)、[RecoveryWorkspace.xaml.cs](../src/Shunshou.App/RecoveryWorkspace.xaml.cs)。引擎源码审查针对官方 [TestDisk / PhotoRec 7.2 源码包](https://www.cgsecurity.org/testdisk-7.2.tar.bz2)，其 SHA256 为 `f8343be20cb4001c5d91a2e3bcd918398f00ae6d8310894a5a9f2feb813c283f`；审查涉及名称生成、元数据改名、配置位置、写出路径及进程参数，不是完整的原生内存安全审计。

## 来源与验证

DiscUtils 按 MIT 许可使用；PhotoRec 与其动态 / 静态依赖各自保留原许可。实际源码、依赖源码、补丁和构建配方以 `RecoverySources-0.3.0.zip` 单独提供，不占用安装目录。详情见 [第三方说明](../THIRD-PARTY-NOTICES.md)及 [恢复源码说明](RecoverySources.md)。

测试采用人工 NTFS 镜像、生成的图片、备份与回收站夹具，不对测试电脑的用户磁盘实施删除或恢复实验。当前已完成和待完成的验证范围见 [0.3.0 验证记录](validation-0.3.0.md)；不要把候选依赖兼容性测试或开发目录 UI 通过，当作所有真实磁盘与最终发布包均已验证。
