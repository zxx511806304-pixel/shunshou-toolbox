# 1.2.0 文字工具、裁剪、压缩包与界面整理验证

日期：2026-09-21。环境：Windows 10 x64（19045）、.NET SDK 10.0.401、WebView2 运行时 153.0.4234.48。测试资料均为程序合成或公开样本，不使用客户资料。本报告区分引擎测试（`tests/Shunshou.SmokeTests --tools`）、应用界面测试（`--verify-v120`）与最终打包测试。

## 引擎与算法（真实输入输出）

- **文本对比**：完全一致的两行判为相同；一行替换报告为“删除 1 行 + 新增 1 行”且行号正确；忽略空格、忽略大小写按需生效；3,000 行 × 3,000 行的超大对比改为整块替换并在结果中标记 `Approximate`，不会卡死界面；超过 4 MB / 20,000 行的输入会被明确拒绝。
- **二维码**：生成 512 px、纠错 H 的 PNG，内容 `https://example.com/顺手工具箱?测试=1` 能被自己识别回完全相同的中文链接；128 px 小图仍可读；纯色图片会明确报告“没有读到二维码”；空内容在写文件之前就被拒绝，且不留下文件。
- **图片裁剪**：800×600 图按 1:1 居中裁出 600×600（偏移 100,0）；像素模式左上、右下取景位置正确；大于原图的裁剪被拒绝；真实输出 16:9 → 800×450，并确认裁剪后原图为非白色区域；原图 SHA256 不变。
- **截取音视频**：6 秒样例视频精确模式截 1.0–3.0 秒，输出时长约 2 秒且同时保留视频与音频；无损复制模式输出可解码、时长在源范围内；终点不晚于起点、负起点都会被拒绝；`00:01:30`、`1:05`、`75` 都能解析为正确秒数；原文件哈希不变。提取音轨用同一引擎生成 MP3。
- **整理 PDF 页面**：4 页样例（3 页有矢量内容、1 页全空）读取为 4 页，空页被标记为“疑似空白”而内容页不会；选择第 3 页旋转 90° 并保留第 1 页后生成的新 PDF 恰好 2 页，旋转值正确、页面尺寸保持；全不选或页码越界都会被拒绝。
- **解压 7z / RAR**：用随包 7-Zip 生成含中文目录与文件的 .7z，解压后中文名、子目录与 4,096 字节文件内容一致；非压缩包扩展名在启动引擎之前就被拒绝。真实 RAR 使用 libarchive 公开测试样本：`test_read_format_rar_windows.rar` 解出 3 个文件（含空目录）、`test_read_format_rar5_multiple_files.rar` 解出 4 个文件；另一个含符号链接与硬链接的 RAR5 样本被**拒绝**并给出“包含符号链接或硬链接”的原因。

## 应用界面（真实窗口，`--verify-v120`）

1. 工具搜索：`二维码` 命中文字工具、`改名` 命中批量重命名、乱码关键词返回空并提示；跳转后收藏、取消收藏生效；空搜索时同时出现“收藏”和“最近使用”。（搜索框自身事件由程序填充建议后走同一条跳转代码；未用脚本模拟物理键盘输入。）
2. 搜索结果发送：把图片发送到“图片裁剪”后输入列表包含该文件；把 .txt 发送到图片工具时被跳过、给出警告且原输入不受影响。
3. 图片裁剪：先由应用进程内直接调用引擎（20 秒超时保护）确认引擎正常，再点“预览当前图片效果”显示预览卡片，最后真实裁剪输出 400×400 正方形。
4. 截取与提取音轨：截取面板与 MP4 选项可见，非法时间被拒绝、`00:00:02` 解析为 2 秒；真实精确截取 1–3 秒生成新 MP4；提取音轨只提供音频格式。
5. 文本对比：统计“新增 1 / 删除 1 / 相同 2”，只显示差异时 2 行、勾选“同时显示相同行”后 4 行。
6. 二维码：识别真实 PNG 得到 `https://example.com/顺手工具箱?v=120`；浅色与深色界面已实际查看。
7. 整理 PDF 页面：读取 4 页；选中最后一页删除后保留 3 页；生成新 PDF 实测 3 页。
8. 解压 7z：真实 .7z 解压出目录与文件。
9. 浅色/深色截图与结果记录保存在同一目录。

## 修复的真实缺陷

- 裁剪预览与裁剪任务在后台线程读取界面控件（比例、像素尺寸、截取方式），在真实窗口中出现卡住或静默失败；现在所有界面取值都在 UI 线程完成后再进入后台任务。
- 侧栏新增搜索框后与“我的工具”标题重叠，已改为标题 + 搜索框的垂直布局。
- 截图预览改用内存流加载图片（与搜索预览一致），避免围绕 FileStream 包装的随机访问流在部分环境下停滞。

## 实际限制

- 只测新增功能与打包，未重跑压缩、PDF 转换、OCR、媒体转换、恢复、卸载等既有功能。
- 二维码纠错级别只在生成端选择，识别端不校验纠错级别；反光、折痕、严重模糊或过小的二维码可能识别失败。
- 含符号链接/硬链接的压缩包被整体拒绝，不做“跳过链接只解压其余文件”的部分解压。
- 未创建 .rar（unRAR 许可不允许用其代码制作压缩器），也不支持分卷压缩包（.part1.rar、.7z.001）。
- 未在干净 Windows 10/11 虚拟机、高对比度主题与混合 DPI 多屏下重测；安装包仍未代码签名。
