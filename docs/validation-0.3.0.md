## 恢复实现与定向验证

`artifacts/v030-recovery-managed-r2/recovery/verification.json` 使用当前 `runtime/recovery/bin`，已验证 DiscUtils 公开只读 NTFS API 配合托管安全写出，以及 PhotoRec 7.2 配合匹配 Cygwin 依赖的真实进程扫描。8 组场景共约 12.70 秒，包含回收站元数据 / 安全复制、源与目标边界、扇区对齐只读流、托管 NTFS 恢复、重复扫描、深度扫描 / 综合查找以及取消。报告确认原始镜像 SHA256 不变。该结果替代早期包含 TestDisk 路线的候选依赖报告；最终程序不再分发或调用 `testdisk_win.exe`。

托管 NTFS 夹具包含主文件表 2 个区段、删除文件 3 个区段与负地址增量、驻留文件、正常删除后释放分配位图但保留未覆盖记录、135 字符中文长名与截断碰撞、`../escape:stream.txt` 路径穿越 / ADS 名。6 个预期文件全部恢复，输出内容与夹具原件的 SHA256 一致；损坏 fixup 和卷外数据区段的 2 条记录跳过，源镜像 SHA256 不变。恶意名称仅作为候选元数据显示，实际副本没有逃出安全目录；相近长名各自保留。扇区对齐流另用拒绝非对齐底层读取的替身验证，未读取真实用户卷。

MFT 跨记录属性列表、压缩 / 加密 / 稀疏文件及额外流不在本版支持范围。夹具哈希一致证明这些生成样本的内容完整，不代表真实磁盘上所有有名称和长度的删除记录都可完整恢复。最终包另由自身携带的 PhotoRec 和 Cygwin 扫描人工镜像，恢复出字节一致的 PNG，镜像源哈希不变。

PhotoRec 源码静态审查核对 7.2 精确源码的文件名生成、嵌入名称清理、配置查找、固定长度路径缓冲区和普通写入模式。适配层使用全新安全会话、短相对输出、隔离用户 / 临时目录环境、关闭自定义签名，最终选中复制使用 `CreateNew`。这是明确路径与配置风险的定向审查，不是完整内存安全审计，也不承诺原生引擎同次扫描的所有重复候选均保留。
